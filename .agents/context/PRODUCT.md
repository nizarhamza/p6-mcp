# Product

## Register

brand

## Users

Planners, schedulers and project controls engineers who work in Oracle Primavera P6 Professional (standalone,
on Windows) on construction, energy and infrastructure projects, and the leads who review their schedules. They
arrive from a search ("Primavera P6 MCP", "DCMA 14-point check with AI", "driving path in P6 with Claude") or
from an MCP directory. They know P6 deeply (F9, total float, data date, XER, baselines, DCMA) and are new to MCP.
The job: understand in a minute what the server does, trust that it will not damage a schedule, install it and
connect their AI client, or follow one concrete guide.

## Product Purpose

The landing site of MCP for Primavera P6, a local MCP server with a Windows installer that lets any MCP client
(Claude, ChatGPT through Codex or a tunnel, Cursor, VS Code) read, analyse and, when allowed, edit P6 schedules:
the P6 Professional database or XER files. It exists to be found for long-tail scheduling queries and to convert
a visit into an installer download. Success: a visitor downloads the installer from the latest GitHub release, or
reads a guide end to end and tries its prompts.

## Brand Personality

Engineer to engineer: precise, calm, credible. Writes like a senior scheduler explaining a tool to a peer: exact
terms (total float, driving path, data date), real prompts and real outputs, limits stated plainly (Windows only,
no EPPM, untested routes marked as such). Confidence comes from specifics, not adjectives.

## Anti-references

- Generic AI SaaS landing pages: gradient text, glass cards, identical icon grids, hero metrics, "supercharge
  your workflow" copy.
- Anything that could pass for Oracle or Primavera branding: no Oracle red, no Oracle layouts or imagery; the
  Oracle marks only appear in descriptive text and the "for Primavera P6" tag line, smaller than "MCP".
- Claims the product cannot back: no testimonials, user counts or ratings that do not exist.

## Design Principles

1. Show the work: real prompts, tool names and result excerpts carry the argument.
2. Safety first, visibly: the write path (dry run, confirmation, backup, edit log) is explained where writes are
   mentioned.
3. Honest scope: say what is not supported or not tested next to what is.
4. Scheduler vocabulary: P6 terms used exactly; MCP explained once, briefly.
5. Fast and quiet: static pages, no tracking, readable on a site laptop over a slow connection.

## Accessibility & Inclusion

WCAG 2.2 AA: text contrast at least 4.5:1, visible focus, full keyboard use, semantic headings and landmarks,
alt text on every image, no information carried by color alone, motion only with a prefers-reduced-motion
alternative. Pages must read well at 200 % zoom and on a phone.
